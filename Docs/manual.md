# FireWallet: Comprehensive Developer Manual & System Architecture Guide

Welcome to the **FireWallet Developer Manual**. This guide is designed so that any engineer, contributor, or judge can immediately understand how the codebase is structured, locate any module or component, and modify features safely.

## 1. Quick Start Guide

### 1.1. Prerequisites
- **Python**: 3.12+
- **Node.js**: 18+
- **UV Package Manager**: Included in `./.bin/uv` or installed globally.

### 1.2. Running the Backend
```bash
# Navigate to backend directory
cd backend

# Install dependencies
../.bin/uv sync

# Run database migrations
../.bin/uv run alembic upgrade head

# Seed demo data (Aster demo user with 5 Trinity buckets and double-entry history)
../.bin/uv run python -m app.jobs.seed

# Start FastAPI development server (port 8000)
../.bin/uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
API Documentation will be live at:
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

### 1.3. Running the Frontend
```bash
# Navigate to frontend directory
cd frontend

# Install dependencies
npm install

# Start Vite dev server (port 5173)
npm run dev
```
Open `http://localhost:5173` in your browser.

### 1.4. Running Tests
```bash
# Run full unit and API test suite (strict mode: zero warnings allowed)
./.bin/uv run --project backend pytest -v -W error
```

## 3. Core Architectural Concepts

### 3.1. The Trinity Bucket Architecture
Money in FireWallet is segregated into 5 immutable buckets:

| Bucket Kind | Display Name | Purpose | Spend Policy |
|---|---|---|---|
| `bank` | Bank Foundation | Operational clearing & emergency runway | **Locked by default**; requires Escape Window override |
| `daily` | Daily Living | Food, coffee, transit, groceries | **Free to spend** up to daily cap; unspent rolls over |
| `freedom` | Freedom Envelope | Guilt-free discretionary entertainment | **Free to spend** until monthly limit reached |
| `vault` | Locked Savings Vault | Long-term savings (20% automated skim) | **Strictly locked**; impossible to spend in-app |
| `bills` | Reserved Bills | Rent, insurance, electricity, utilities | **Strictly locked**; only releases for verified bills |

### 3.2. Bank-Kept Double-Entry Ledger
All internal money movements (e.g. Payday allocations, savings skims) record **two paired legs** sharing the same `transfer_id`:
- **Debit leg** (`-amount`) on source bucket.
- **Credit leg** (`+amount`) on destination bucket.
- $\sum \text{legs} = 0$ (Zero-sum reconciliation invariant).

External merchant payments record a debit leg on `Daily` or `Freedom` tagged with `counterparty_bucket="paypal_merchant"`.

### 3.3. Zero-Float Integer Accounting
**Rule:** Floating-point numbers are prohibited in the accounting engine. All monetary values are represented as signed 64-bit integers in **minor currency units** (cents for USD):
- `$24.50` $\rightarrow$ `2450`
- `$1,200.00` $\rightarrow$ `120000`

## 5. Developer Recipes (How To...)

### Recipe 1: How to Add a New Database Field and Migrate
1. Edit the SQLModel definition in `backend/app/models/<model>.py`.
2. Generate an autogenerated Alembic migration:
   ```bash
   cd backend
   uv run alembic revision --autogenerate -m "add_field_name_to_table"
   ```
3. Inspect the generated migration in `backend/alembic/versions/`. Ensure any non-nullable column includes `server_default`.
4. Apply the migration:
   ```bash
   uv run alembic upgrade head
   ```

### Recipe 2: How to Add a New Trinity Firewall Spending Rule
1. Open [`backend/app/ledger/engine.py`](file:///home/aster42/projects/full-stack/FireWallet/backend/app/ledger/engine.py).
2. Locate the `can_spend()` method in `LedgerEngine`.
3. Add your deterministic rule condition. Ensure it returns `(allowed: bool, reason: str, needs_override: bool)`.
4. Add a matching unit test in `tests/unit/test_trinity_rules.py`.
5. Run tests: `./.bin/uv run --project backend pytest -v -W error tests/unit/test_trinity_rules.py`.

### Recipe 3: How to Add a New Column to the Desktop AG Grid
1. In [`frontend/src/features/analytics/DeepLedgerGrid.jsx`](file:///home/aster42/projects/full-stack/FireWallet/frontend/src/features/analytics/DeepLedgerGrid.jsx), locate the `columnDefs` array.
2. Add your new column object:
   ```javascript
   {
     field: 'my_field',
     headerName: 'My Field',
     width: 140,
     sortable: true,
     filter: 'agTextColumnFilter',
     cellRenderer: (params) => (
       <span className="text-slate-300">{params.value}</span>
     )
   }
   ```
3. Ensure backend schema in [`backend/app/schemas/common.py`](file:///home/aster42/projects/full-stack/FireWallet/backend/app/schemas/common.py) (`DeepLedgerItem`) includes `my_field`.

### Recipe 4: How to Test PayPal Webhooks Locally

2. Post a sample webhook payload with mock headers:

   ```bash
     }'
   ```
3. Verify event is logged with `status="processed"` in table `paypal_webhook_events`.

### Recipe 5: How Dollar Words & NLP Short-Tags Work
1. User input like `"Can I spend twenty dollars on takeout?"` is parsed:
   - Amount: `parse_amount_cents_from_text("... twenty dollars ...")` $\rightarrow$ `2000` cents.
   - Tag: `distill_short_tag("... takeout ...")` $\rightarrow$ `"takeout"`.
2. Historical intents and coach messages matching `"takeout"` are fetched via `retrieve_rag_context()`.
3. If allowed by Trinity rules, a 1-tap `ActionCard` is generated with `amount_cents: 2000` and `target_bucket: "daily"`.
